# Architecture map

Where code lives, for both apps. This is a map, not a contract: it can go stale, so trust the code
when they disagree, and update this file in the same PR when you add, move or rename a module.
Conventions and invariants agents must follow are in [`AGENTS.md`](../AGENTS.md); product rules are
in [`SPEC.md`](SPEC.md).

## Frontend Structure

- `src/App.vue`: Root component
- `src/main.ts`: Entry point (Vue app initialization)
- `src/router/`: Vue Router routes
- `src/stores/`: Pinia state management (`auth.ts`, `settings.store.ts`, `contentBlocks.store.ts`, `indicators.store.ts`, `indicatorTables.store.ts`, `pages.store.ts`, `maps.ts`, `rtLeaders.store.ts`, `audit.store.ts`, `auditRetention.store.ts`, `comparisonTemplates.store.ts`, `weatherConfig.store.ts` — Admin-only weather settings, sends only the refresh interval)
- `src/components/data/`: CMS forms and cards (`ScalarIndicatorForm.vue`, `TableIndicatorForm.vue`, `ContentBlockForm.vue` — a thin dispatcher to the per-block forms in `blocks/` (Hero, Sambutan, Profil, Highlights, Cerita prose; shared frame `BlockFormShell.vue`, row helpers in `blockFormShared.ts`, placement/kind registry in `blockMeta.ts`; no JSON editor), `IndicatorCard.vue`)
- `src/views/DataManagementView.vue`: Consolidated `/data` CMS view with tabbed management of indicators and content blocks; its Admin-only settings tab only links to `/admin/sistem/konfigurasi`
- `src/views/AdminRukunTetanggaView.vue`: `/admin/rukun-tetangga` CMS for official roster edits, and CSV preview/apply
- `src/views/AdminPetaView.vue`: `/admin/peta` map-point management (SPEC §8) — list/map split, search and type filter, create/edit/delete dialogs, coverage-problem notices. Reuses `InteractiveMap` and `LocationPicker`, reloads the maps store and RT roster after every write, and never edits Ketua RT contacts (those stay in the RT view)
- `src/views/AdminPublikasiView.vue`: `/admin/publikasi` publication catalog (SPEC §8) — a single-column card list with search, category filter, Urutkan, select-all, bulk delete and drag reorder; one dialog per add/edit (`src/components/admin/publikasi/PublikasiItemForm.vue`), a delete confirmation, and the title/intro dialog (`PublikasiCatalogInfoForm.vue`). `PublikasiCardList.vue` renders `PublikasiCard.vue` (grip, checkbox, cover via `useAuthenticatedBlobUrl` on the preview path, facts, actions). Every change builds the whole list and saves through `PUT /api/publikasi/catalog` (via `store.savePublikasiCatalog`) with the block's `updatedAt`; the view holds a snapshot of the block so a stale-write refetch never drops an open draft.
- `src/components/admin/cards/`: shared card-list parts used by `/admin/cerita` and `/admin/publikasi` — `CardListToolbar.vue`, `CardSearchField.vue`, `SelectAllButton.vue`, `SortToggleButton.vue` (Urutkan, with its icon), `CardActionButton.vue` (outlined card action; `href` makes it a link), `CardSelectionBar.vue` (with the bulk "Hapus semua" icon), `CardSelectCheckbox.vue`, `CardDragGrip.vue`, `CardDropIndicator.vue`, `BulkDeleteDialog.vue` (generic bulk report, noun and intro supplied by the caller) and `cardTypes.ts`. `src/composables/useCardSelection.ts` (checked cards, tri-state select-all, prune to visible) and `src/composables/useCardDragReorder.ts` (drag state and drop index in the full order) hold the logic.
- `src/views/AdminCeritaPreviewView.vue`: the bare route `/admin/cerita/pratinjau` (no admin shell, no public layout; `router/index.ts`, editors only) that draws the section preview with the reader's `SectionProse` and `ArticleFigure`. It accepts a `cerita-preview` message only from its parent window of the same origin (`utils/ceritaPreviewMessage.ts` holds the protocol, the origin and source check and the payload shape check) and reports `cerita-preview-ready` and its content height back. `utils/ceritaPreviewFigure.ts` maps the figure draft to an `ArticleFigure` through the public mapping
- `src/views/AdminCeritaView.vue`: `/admin/cerita` Cerita management (SPEC §8) — the default page-card list (search, always-visible checkboxes with a tri-state select-all, drag and drop on the card grip (off during search or save), Urutkan mode with Naik / Turun, bulk delete report) and, at `?halaman=<slug>`, the editor: the structure tree (left), the selected section's text and figure (centre) and the live preview of the draft (right from 1536px; below the cards before that). The selection lives in the URL (`bab`, `bagian`). Owns the dialogs, focus hand-back and the unsaved-work guard for the centre column; all writes go through `stores/ceritaAdmin.store.ts`. The route sets `meta.fullBleed`, which `layouts/AdminLayout.vue` reads to drop the padded card

exposes `save()` for the header's Simpan perubahan), `CeritaLivePreview.vue` (the "Pratinjau langsung" panel: posts the unsaved draft to a same-origin iframe of `/admin/cerita/pratinjau`, sizes it from the height it reports; Desktop 1280px scaled, Ponsel 390px), `CeritaNameDialog.vue` / `CeritaPageDetailsDialog.vue` (optional headline and byline of a page) / `CeritaDeleteDialog.vue` (one-line title and delete confirmation), `CeritaSectionEditor.vue` (title, one body and figure; `save()` writes the text, then the figure; reports busy, dirty and the draft), `CeritaSectionText.vue` (the text card: "Judul bagian" and "Isi" with the limited-Markdown toolbar, SPEC §8), `CeritaFormatToolbar.vue` (format buttons for the body), `CeritaFigureEditor.vue` (the "Jenis figur" tiles: 1 gambar, 2 gambar, Galeri, Grafik; one draft per kind; the Grafik tile reads the page's indicator tables from `indicatorTables.store.ts`) / `CeritaFigurePhotoRow.vue` (one photo, laid out as single, pair or gallery), and `ceritaDomIds.ts` (element ids the view focuses); `utils/ceritaTreeLabels.ts` (tree numbering and figure labels); `utils/ceritaChapterOverview.ts` (overview excerpt, figure and completeness badges, thumbnail photo); `composables/figureKindHint.ts` (one-shot `pendingFigureKind` hand-off from "Tambah bagian baru" to the figure editor, read with `consumePendingFigureKind()`); `composables/useStoredFigurePreview.ts` (preview photos as blob URLs through `fetchMediaPreviewBlob`, and a chart's table through `indicatorTables.store.ts`, drawn by the public `ArticleFigure`); `composables/figureKindHint.ts` (one-shot tile hand-over from the chapter overview). `composables/useKeyboardReorder.ts` (keyboard ordering on a grip: Spasi picks up, arrows move with a live preview through `arrange()`, Spasi drops and saves through `onMove`, Escape or blur cancels; unit-tested in `__tests__/useKeyboardReorder.spec.ts`), used by the tree (chapters and sections), the overview cards and the gallery, beside the pointer `composables/useCardDragReorder.ts`; `components/admin/cards/ReorderGripButton.vue` (the grip as a real button, with pointer drag on its wrapper). Figure draft rules and validation: `src/utils/ceritaFigureDraft.ts`; wording: `src/utils/ceritaAdminMessages.ts`; sibling-swap reorder body: `src/utils/ceritaOrder.ts`
- `src/stores/ceritaAdmin.store.ts`, `src/services/ceritaAdmin.service.ts`, `src/services/ceritaFigure.service.ts`: the Cerita management store (reads the shared pages and content-block stores, resolves `expectedUpdatedAt` at call time, refreshes both caches after each write), the hierarchy/paragraph write calls, and every section-figure call (the one file to change if the figure contract moves). `contentBlocks.store.ts` `editableBlocks` excludes `figure` blocks
- `src/services/media.service.ts`, `src/composables/useAuthenticatedBlobUrl.ts`, `src/components/common/MediaPhotoField.vue`: editor media upload (multipart through `apiFetch`, which leaves `Content-Type` to the browser for FormData), plain-Indonesian text for every media error code, authenticated preview as a revoked-on-change blob URL, and the reusable photo field (pick or drop, upload with a purpose, replace, remove)
- `src/views/AdminDashboardView.vue`: `/admin` Beranda (SPEC §8) — shortcuts from `adminNav.ts`, data health, recent content changes and an Admin-only security block. State in `stores/dashboard.store.ts` (`GET /api/dashboard`; backend `dashboard.service.ts`).

- `src/views/AdminKonfigurasiSistemView.vue`: Admin-only `/admin/sistem/konfigurasi` — four independent sections (portal identity and contact, starting map view, weather, log retention) built from `src/components/admin/config/` (`ConfigSection.vue`, `PortalSettingsSection.vue` wrapping `PublicSettingsForm.vue` with `part="identity"` or `"map"`, `WeatherConfigSection.vue`, `AuditRetentionSection.vue`). Refresh presets live in `src/utils/weatherRefresh.ts`. `/settings/audit-retention` is a router redirect to its retention section
- `src/components/templates/`: `ComparisonTemplateForm.vue` (name, sentence and variants, debounced live preview, trend-keyword acknowledgment, save) and `TemplateSentenceBuilder.vue` (ordered text/chip parts with add/remove/move buttons — the editor never shows placeholder syntax). Chip names, segment parse/serialize, validation and generated lookup keys live in `src/utils/comparisonTemplateSegments.ts`; `ScalarIndicatorForm.vue` carries the Editor's "Templat kalimat perbandingan" selector
- `src/views/CeritaPageView.vue` / `src/components/cerita/`: the public Cerita reader — `CeritaPageView.vue` owns the loading / not found / failed / ready state machine (per-slug outcomes from `pages.store.ts`, a load token that discards superseded loads), the chapter scroll spy and deep-link scroll; `CeritaHero`, `CeritaStatePanel`, `CeritaLoadingState` are the navy title band and state screens; `ChapterToc` is the desktop rail and the sticky mobile chapter selector; `ChapterSection` renders a chapter with its empty / partial-failure states and each section's stored figure (SPEC §8); `ArticleFigure` (with `FigureCard`, `FigurePhotoPair`, `FigureCarousel`, `FigureDiagram`, `FigureChart`) picks the figure layout, drops photos that fail to load and reports through `visible-change` when nothing is left; `FigureChart` draws a chart from the page's indicator tables (`chartTablesById`, passed down from `CeritaPageView`), with `common/BarDiagram.vue` for bars and CSS columns otherwise; `utils/ceritaChart.ts` is the pure row-to-value mapping; `utils/ceritaStoredFigure.ts` is the pure, defensive mapping from a `figure` content block's metadata to an `ArticleFigure` (public photo path `/api/media/<mediaId>`) `SectionProse` renders one stored paragraph from its limited-Markdown AST with real elements (no `v-html`); `utils/proseMarkdown.ts` is the pure parser (http/https/mailto links only, linear time, input capped at 50 000 characters) plus the toolbar's text helpers; `admin/cerita/CeritaFormatToolbar.vue` is the editor's formatting toolbar.

Click/drag, direction and zoom buttons and a labelled keyboard mode (arrows and direction buttons pan the basemap in both modes; in pin mode the pin keeps its screen position); no coordinate or zoom fields. Optional device-location draft. Used by `RtLocationPicker.vue`, `PublicSettingsForm.vue` and `PointEditorForm.vue`; pure geometry helpers live in `src/utils/geoPicker.ts`

- `src/layouts/`: `AdminLayout.vue` — the admin/CMS base layout shell (sidebar, header, breadcrumb) every `/admin`, `/data`, `/users` and `/audit-logs` route is mounted inside; `PublicLayout.vue` — the public shell (skip link, `AppNavbar` + `PublicNavigationMenu`, the single `<main id="main-content">`, `AppFooter`, public-settings and page-hierarchy load) that `App.vue` wraps around every route with `meta.layout: 'public'`. Public views must not render their own `<main>`, navbar, footer or skip link; `meta.headerOverlay` (Home only) makes the header overlay the hero. `publicShell.ts` is the injection key `TentangPageLayout` (now a thin compatibility wrapper) uses to avoid doubling the shell
- `src/components/common/AlertBanner.vue`, `src/utils/userMessages.ts` (`isRetryable`, `toUserMessage`), `authStore.sessionEnded` + `layouts/AdminLayout.vue`: admin error presentation. Stores keep an `errorKind` next to their error string; banners pass it as `kind` so retry is offered only when it can help and session failures defer to the single session-ended notice in the layout. `utils/safeRedirect.ts` validates the post-login `redirect` query
- `src/components/common/AppNavbar.vue` / `PublicNavigationMenu.vue`: the public header bar (background `variant` navy/transparent is separate from `foreground`; modal sheet below `md`, anchored panel from `md`) and the menu content (Beranda, Cerita/Sumber Daya/Tentang groups, one role-aware account area). Cerita links come from the `pages` store with fallbacks in `config/publicNav.ts`

Pure rules and wording are in `src/utils/adminMapPoints.ts`; the write calls are in `src/services/adminMaps.service.ts`
- `src/config/publicNav.ts`: public navigation data — footer link lists, the Cerita/Sumber Daya/Tentang groups, exact-destination active matching and the Cerita fallback links
- `src/utils/bodyScrollLock.ts`: ref-counted body scroll lock shared by `BaseModal` and the mobile menu
- `src/config/adminNav.ts`: Single role-to-items source of truth for the admin sidebar, also read by the router guards (`src/router/index.ts`) so sidebar visibility and route access can't drift apart
- `src/composables/`: `useAdminHeader.ts` (admin shell header channel: `setAdminHeader(title, subtitle, { trail, compact })` sets the title, subtitle, an optional breadcrumb `trail` override and a `compact` flag; every call replaces all four, and `AdminLayout` calls it on each path change so a view's trail never leaks to another page; `ADMIN_HEADER_TITLE_ID` is the h1 id a view focuses), `useDrawerFocusTrap.ts` (mobile drawer focus trap, visibility filter, and Escape handling), `usePublicHeaderState.ts` (public header background state and the single `HEADER_SCROLL_THRESHOLD_PX`), `useGeolocation.ts` (session-wide, deduplicated, permission-aware visitor location for the public map; in memory only), `useIsDesktop.ts` (reactive `md` desktop breakpoint media query), `useMediaQuery.ts` (reactive `matchMedia` for a screen's own breakpoint), `useLogout.ts` (shared logout flow)

- `src/assets/`: Static assets, including `main.css` (Tailwind entry, imported in `main.ts`)

## Backend Structure

- `src/index.ts`: Entry point — starts the HTTP listener
- `src/app.ts`: Express app setup (middleware, CORS, route mounting)
- `src/configs/index.ts`: Typed env var access; validated at boot
- `src/routes/`: Route definitions (`auth.routes.ts`, `health.routes.ts`, `profile.routes.ts`, `users.routes.ts`, `weather.routes.ts`, `audit.routes.ts`, `settings.routes.ts`, `maps.routes.ts`, `contentBlocks.routes.ts`, `pages.routes.ts`, `chapters.routes.ts`, `sections.routes.ts`, `indicators.routes.ts`, `indicatorTables.routes.ts`, `comparisonTemplates.routes.ts`)
- `src/controllers/`: Decoupled route handlers (`auth.controller.ts` for local auth, `oauth.controller.ts` for Google OAuth, `otp.controller.ts` for OTP verification, `profile.controller.ts` for self-service credential changes, `users.controller.ts` for user management, `weather.controller.ts` — forecast lookup, `audit.controller.ts` — audit log list/summary/acknowledge, `settings.controller.ts` — public portal settings, audit retention config, and operational weather forecast settings, `maps.controller.ts` — spatial points and RT leader lookup (plus editor/admin write endpoints for spatial points, their RT coverage, and RT leader edits), `pages.controller.ts` — public page/chapter/section read and editor page management (create, rename, delete, reorder), `chapters.controller.ts` — chapter create/update/delete/reorder, `sections.controller.ts` — section create/update/delete/reorder, section prose block create/reorder, the section text `PUT` and the section figure `PUT`/`DELETE` (all via the shared `hierarchyHandler.ts` wrapper),  `contentBlocks.controller.ts` — CMS prose/content block queries, edits and prose block delete, `indicators.controller.ts` — public indicator reads and editor/admin CRUD, `indicatorTables.controller.ts` — public matrix-table reads (slug-or-id) and editor/admin table/row CRUD, `comparisonTemplates.controller.ts` — tier-1 comparison template CRUD, the 422 keyword-acknowledgment response, and the Admin-only `POST /preview` live-preview handler)
- `src/services/pageHighlights.service.ts` (backend): per-topic landing-card highlights (SPEC §8) behind `GET /api/pages/highlights` and `GET`/`PUT /api/pages/:slug/highlights`. Frontend: `stores/pageHighlights.store.ts`, `components/admin/cerita/CeritaHighlightsPanel.vue`.
- `src/services/`: Business logic sitting between controllers and external/data sources (`users.service.ts` — user management & role administration, `profile.service.ts` — self-service credential updates, `weather.service.ts` — caches and transforms BMKG forecasts, `audit.service.ts` — audit log writes/reads and the `AUDIT_ACTIONS` severity table, `settings.service.ts` — public portal, audit retention, and operational weather settings, `maps.service.ts` — spatial points querying, RT leader coordinate resolution, editor/admin spatial point/coverage/RT-leader writes, CSV roster preview/apply, and the explicit sample-roster status with the shared ketua_rt 1:1 invariant enforcement (SPEC §7), and audit, `legacySampleRtCleanup.service.ts` — shared transactional seed/CLI cleanup and count-only maintenance audit, `pages.service.ts` — page → chapter → section hierarchy reads, atomic page creation, rename, deletion, and deadlock-free reordering, `chapters.service.ts` / `sections.service.ts` — chapter and section authoring (generated slugs, `expectedUpdatedAt` optimistic concurrency, parent-first locking, dependency-blocked deletes, audit in the same transaction), `hierarchyDependencies.service.ts` — content block/indicator/table dependency counts for delete safety, `hierarchyCaches.ts` — indicator cache invalidation after hierarchy removals, `contentBlocks.service.ts` — CMS prose/content block queries and edits plus section prose block create/delete/reorder, `sectionText.service.ts` — save a section's title and its one prose body together (merges legacy multi-block sections), `sectionClone.service.ts` — move a section to another chapter of the same page and duplicate a section with its prose and figure (chapters locked in ascending id order, then the section), `sectionFigure.service.ts` — the single photo/photos/diagram/chart figure per section (`figure` content block): lock section → figure block → affected media in ascending id order, `attachMedia`/`detachMedia` in the same transaction, no-op detection (an identical re-save still re-asserts the attach), audit, cache invalidation (generic content-block PATCH/DELETE refuse figure blocks with 409 `FIGURE_BLOCK_PROTECTED`), `indicators.service.ts` — scalar figure CRUD with tier-1 pairing validation, template attachment and rendered `comparison`, and audit, chart-figure table references (same-page check, count of charts using a table), `comparisonTemplates.service.ts` — admin-authored sentence templates with warn-on-save trend-keyword acknowledgment and - `src/utils/`: `jwt.ts` (token signing), `oauth.ts` (Google OAuth PKCE & token verification), `otp.ts` (OTP hashing & expiry), `mailer.ts` (transactional email), `turnstile.ts` (Turnstile API client), `prisma.ts` (Prisma instance — wraps `audit_logs` writes in an append-only guard, see Audit Trail below), `bmkg.ts` (BMKG API fetch + response validation), `auditLogGuard.ts` (the append-only guard's pure logic), `actor.ts` / `requestContext.ts` (pull `{id, email, role}` and `{ipAddress, userAgent}` off a request for audit entries), `lockTransactionCache.ts` (versioned TTL cache and row-level lock transaction scaffold), `hierarchyAuthoring.ts` (shared Cerita authoring primitives: `HierarchyServiceError` codes, title/slug generation, `expectedUpdatedAt` checks, reorder planning), `comparator.ts` (canonicalized JSON deep equality for diffs and mutations), `sectionFigure.ts` (figure zod schema, limits and media-id helpers; pure), `keyedCache.ts` (generic bounded LRU keyed cache with recency tracking), `comparisonProse.ts` (tier-1 template structure validation and exact-decimal comparison rendering), `trendKeywords.ts` (the code-owned trend/superlative word list, matcher, and per-occurrence acknowledgment key), `rtSeedPoints.ts` (deterministic RT seed ids and deletion tombstones), `legacySampleRtFingerprints.ts` (fingerprints for recognized legacy synthetic RT records)
- Publication catalog (SPEC.md §4, §8): `src/routes/publikasi.routes.ts` + `src/controllers/publikasi.controller.ts` + `src/services/publikasiCatalog.service.ts` — `PUT /api/publikasi/catalog` locks the `publikasi-katalog` block, attaches/detaches document and cover assets in the same transaction (ReadCommitted, assets locked in ascending id order), derives file type and size from the asset, audits counts and the titles of added, changed, removed and reordered rows (never file names, paths or ids); the generic content-block PATCH refuses this block's metadata (`PUBLIKASI_BLOCK_PROTECTED`)
- Media storage (SPEC.md §7 `media_assets`): `src/routes/media.routes.ts` + `src/controllers/media.controller.ts` (upload, editor preview, public image, public download), `src/middlewares/mediaUpload.middleware.ts` (multer disk staging into `<UPLOAD_DIR>/_staging/<uploadId>/`, one file per request), `src/services/media.service.ts` (validate, re-encode, store, audit; exports `attachMedia(tx, ids, {purpose})` / `detachMedia` for content transactions), `src/services/mediaCleanup.service.ts` + `scripts/cleanup-media.ts`, and `src/utils/`: `uploadRoot.ts` (UPLOAD_DIR resolution and boot validation), `mediaPolicy.ts` (every limit, allowed type and the purpose allowlist), `mediaSignature.ts` (magic-byte detection, OOXML inspection), `mediaCsv.ts` (streaming CSV scan: UTF-8/control-char sanity and formula-injection rejection), `mediaImage.ts` (sharp WebP re-encode, EXIF stripping, thumbnails), `mediaStorage.ts` (layout, realpath containment, display-name and header helpers)
- `prisma/schema.prisma`: ORM schema (MySQL)
- `prisma/seed.ts`: Seeds default roles (`user`, `admin`, `editor`), default audit retention settings (keep-forever), default public settings (`publicSeedMap`), default operational weather config, default content blocks (`DEFAULT_CONTENT_BLOCKS`), default tier-1 comparison templates (`DEFAULT_COMPARISON_TEMPLATES`), the 8 Cerita pages and their chapters (data in `prisma/ceritaPages.ts`), sample RT leaders (development/testing only, skipped when NODE_ENV=production), and spatial points; delegates legacy cleanup to `legacySampleRtCleanup.service.ts`
- `prisma/seedRtLeaders.ts`, `src/data/rtLeadersData.ts`: create-only RT seed helpers and the development-only synthetic map/contact data
- `backend/src/utils/rtLeadersCsv.ts`: CSV parsing and validation for the Ketua RT operational import
- `prisma/seeder_indicator.ts`: Seeds sample scalar indicator figures across all 8 Cerita categories (`npm run seed:indicator`)
- `generated/prisma/`: Auto-generated Prisma client (do not edit)
- `scripts/grants/audit-logs-grants.sql`, `scripts/prune-audit-logs.ts`, `scripts/cleanup-legacy-sample-rt-leaders.ts`: audit trail operations and development sample cleanup — see Audit Trail below

`GET /api/maps/rt-leaders` includes `isSampleRoster`, sourced from
`maps.rt_leaders_sample_roster`. The Ketua RT page keeps roster rows and that flag from the same
successful response and revalidates every 60 seconds while visible.

Key details:

- Express app with JSON middleware, cookie parsing, CORS, and route mounting under `/api/*`
- CSRF protection is applied globally after `cookie-parser`/`cors`; fetch a token from `/api/auth/csrf-token` and send it in `x-csrf-token` for mutating auth requests
- Prisma client output to custom location `../generated/prisma`
- JWT access + refresh tokens; refresh tokens persisted in DB with `/api/auth/refresh` and `/api/auth/logout` endpoints
- Uses `dotenv` for environment configuration
- Unit tests under `src/__tests__/` run via Node's built-in test runner through `tsx` (`npm test`). `npm run test:coverage` runs the same suite with `--experimental-test-coverage` via `backend/scripts/coverage.mjs`, which strips `src/__tests__/**` and `generated/**` out of the printed report so the numbers reflect application code only
